**한국어 DPO Fine-tuning + vLLM + FastAPI + RunPod 서비스 프로젝트**


## 구현 범위

프로젝트는 다음 전체 파이프라인으로 구성했습니다.

```text
한국어 선호 데이터 작성
        ↓
데이터 구조 검증
        ↓
Qwen2.5-1.5B-Instruct 기반 QLoRA DPO 학습
        ↓
LoRA Adapter 저장
        ↓
Base 모델과 Adapter 병합
        ↓
vLLM OpenAI 호환 서버 실행
        ↓
FastAPI 한국어 LLM 서비스
        ↓
Base 모델과 DPO 모델 성능 평가
        ↓
블라인드 사람 평가
```

DPO는 동일한 질문에 대한 `chosen` 답변과 `rejected` 답변을 이용해 선호 방향을 직접 학습하며, 별도의 Reward Model 없이 선호 최적화를 수행하는 방식입니다. TRL은 이를 위한 `DPOTrainer`를 제공합니다. ([Hugging Face][1])

# 단계별 실행 요약

## 1. RunPod 프로젝트 경로

권장 원격 경로:

```text
/workspace/korean_dpo_vllm_runpod_service
```

로컬 PyCharm 경로 예시:

```text
C:\LLM_workspace\korean_dpo_vllm_runpod_service
```

RunPod Pod에서는 HTTP 포트 `8000`, `8001`을 노출합니다. 기존 Pod 또는 템플릿의 HTTP 포트는 RunPod의 Pod 설정에서 추가할 수 있습니다. ([Runpod Documentation][2])

* `8000`: FastAPI 서비스
* `8001`: vLLM OpenAI 호환 서버

RunPod의 기본 프록시 SSH는 SCP와 SFTP를 지원하지 않을 수 있으므로, PyCharm 파일 동기화가 필요할 때는 직접 TCP SSH 설정이나 Git을 사용하는 것이 안전합니다. ([Runpod Documentation][3])


DPO 데이터 형식:

```json
{
  "prompt": [

    },

    }
```

## 5. QLoRA DPO 학습

```bash
python training/train_dpo_qlora.py \
  --base-model Qwen/Qwen2.5-1.5B-Instruct \
  --train-file data/dpo_train.jsonl \
  --eval-file data/dpo_eval.jsonl \
  --output-dir models/dpo_adapter \
  --epochs 1 \
  --batch-size 1 \
  --gradient-accumulation-steps 8 \
  --learning-rate 5e-6 \
  --beta 0.1 \
  --max-length 1024
```

프로젝트의 DPO 학습 코드는 다음을 적용합니다.

* 4비트 NF4 양자화
* Double Quantization
* BF16 또는 FP16 자동 선택
* LoRA
* Gradient Checkpointing
* Paged AdamW 8-bit
* Training/Evaluation Dataset 분리
* DPO 평가 지표 저장
* Adapter와 Tokenizer 저장

LoRA는 전체 모델 가중치를 모두 학습하지 않고 저차원 행렬을 추가해 학습 파라미터와 메모리 사용량을 줄이는 PEFT 방식입니다. ([Hugging Face][4])

## 6. Adapter 병합

```bash
python training/merge_adapter.py \
  --base-model Qwen/Qwen2.5-1.5B-Instruct \
  --adapter-path models/dpo_adapter \
  --output-dir models/merged_model \
  --dtype bfloat16
```

PEFT의 `merge_and_unload()`를 이용하면 LoRA Adapter를 Base 모델에 병합하여 독립 모델처럼 저장할 수 있습니다. 별도 Adapter 로딩 오버헤드를 줄이고 일반적인 추론 서버에서 사용하기 쉬워집니다. ([Hugging Face][5])

## 7. vLLM 설치

학습 환경과 분리된 가상환경을 사용합니다.

```bash
deactivate

python -m venv .venv-vllm
source .venv-vllm/bin/activate

python -m pip install --upgrade pip
pip install -r requirements-vllm.txt
```

vLLM은 OpenAI 호환 Chat Completions API를 제공하므로 FastAPI 서비스에서 OpenAI Python Client 형식으로 호출할 수 있습니다. ([vLLM][6])

## 8. DPO 모델 vLLM 실행

```bash
chmod +x scripts/*.sh

./scripts/run_vllm_dpo.sh
```

내부 실행 구조:

```bash
vllm serve /workspace/korean_dpo_vllm_runpod_service/models/merged_model \
  --host 0.0.0.0 \
  --port 8001 \
  --api-key local-vllm-key \
  --served-model-name korean-dpo-model \
  --dtype auto \
  --gpu-memory-utilization 0.90 \
  --max-model-len 4096
```

vLLM은 병합 모델뿐 아니라 LoRA Adapter를 OpenAI 호환 서버에서 제공하는 방식도 지원합니다. 이 프로젝트에서는 실행 구조를 단순화하기 위해 병합 모델을 기본 방식으로 사용했습니다. ([vLLM][7])

# 파인튜닝 모델 평가

## 1. Base 모델 예측 생성

Base 모델 vLLM 서버 실행:

```bash
source .venv-vllm/bin/activate
./scripts/run_vllm_base.sh
```

별도 터미널:

```bash
source .venv-service/bin/activate

python evaluation/generate_predictions.py \
  --output-file outputs/base_predictions.jsonl
```

## 2. DPO 모델 예측 생성

Base vLLM을 종료하고 DPO 모델을 실행합니다.

```bash
source .venv-vllm/bin/activate
./scripts/run_vllm_dpo.sh
```

예측 생성:

```bash
source .venv-service/bin/activate

python evaluation/generate_predictions.py \
  --output-file outputs/dpo_predictions.jsonl
```

## 3. 자동 평가

Base 모델:

```bash
python evaluation/calculate_metrics.py \
  --prediction-file outputs/base_predictions.jsonl \
  --output-file outputs/base_metrics.json
```

DPO 모델:

```bash
python evaluation/calculate_metrics.py \
  --prediction-file outputs/dpo_predictions.jsonl \
  --output-file outputs/dpo_metrics.json
```

## 4. 평가 지표

프로젝트에 포함된 평가 지표는 다음과 같습니다.

* Exact Match
* ROUGE-1
* ROUGE-2
* ROUGE-L
* JSON 형식 준수율
* 한국어 답변 포함률
* 평균 Latency
* 중앙값 Latency
* P95 Latency
* 초당 생성 토큰 수

## 5. Base와 DPO 비교

```bash
python evaluation/compare_models.py
```

결과 파일:

```text
outputs/comparison.json
```

비교 결과 구조:

```json
{
  "rougeL_f1": {
    "base": 0.31,
    "dpo": 0.46,
    "improvement_delta": 0.15
  },
  "average_latency_seconds": {
    "base": 0.81,
    "dpo": 0.85,
    "improvement_delta": -0.04
  }
}
```

품질과 처리량은 변화량이 양수일 때 개선입니다. Latency는 DPO 모델이 더 빠를 때 변화량이 양수가 되도록 계산했습니다.

## 6. 블라인드 사람 평가

```bash
python evaluation/create_blind_review.py
```

생성 파일:

```text
outputs/human_review.csv
outputs/human_review_answer_key.json
```

평가 항목:

* 정확성
* 질문 관련성
* 한국어 자연스러움
* 친절성
* 안전성
* A/B/TIE 선호

DPO 모델은 기준 답변과 문장이 완전히 같지 않아도 더 자연스럽거나 안전한 답을 생성할 수 있으므로, ROUGE만으로 성공 여부를 판단하면 안 됩니다. 자동 지표와 블라인드 사람 평가를 함께 확인해야 합니다.

## 테스트 및 검증

프로젝트 생성 후 포함된 Python 파일 전체에 대해 문법 컴파일 검사를 수행했으며 문법 오류는 발견되지 않았습니다.

FastAPI 단위 테스트:

```bash
source .venv-service/bin/activate
pytest -q
```

단위 테스트에서는 실제 vLLM 호출을 모의 처리하므로 GPU 서버 없이도 FastAPI 라우팅과 응답 스키마를 확인할 수 있습니다.

실제 DPO 학습, Adapter 병합, vLLM GPU 추론은 현재 환경에서는 실행하지 못했습니다. RunPod에서 다음 순서로 실제 통합 테스트해야 합니다.

```text
GPU 확인
→ 데이터 검증
→ DPO 학습
→ Adapter 파일 확인
→ 병합 모델 생성
→ vLLM 모델 목록 확인
→ 직접 Chat API 호출
→ FastAPI 연결 확인
→ Base/DPO 평가 실행
```
