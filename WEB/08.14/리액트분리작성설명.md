**최종 동작 구조는 `React → Django → FastAPI`입니다.** React는 FastAPI를 직접 호출하지 않으며, RAG·이미지 캡셔닝·이미지 생성·STT·TTS뿐 아니라 생성 이미지와 TTS 음원 조회까지 Django를 경유하도록 구성했습니다.

기존 서비스 기능은 유지했습니다. 회원가입/로그인/로그아웃/세션, 프로필 수정·탈퇴, 관리자 회원관리, 게시판 검색·페이징·CRUD·조회수·첨부파일·권한, RAG, PDF 근거 조회, 이미지 캡셔닝, Stable Diffusion 이미지 생성, 마이크 STT, TTS 기능을 React 화면으로 구현했습니다.

Django에는 React용 `/api/` 계층만 추가했습니다.

최종 구조는 다음과 같습니다.

```text
final/
├─ react_frontend/       ← React + Vite + Bootstrap
├─ django_web/           ← Django 백엔드 + REST형 JSON API
├─ fastapi_ai/           ← 기존 AI/RAG 서버
│
├─ start_react.bat
├─ start_django.bat
├─ start_fastapi.bat
└─ start_all.bat
```

React에는 다음 화면이 포함되어 있습니다: 홈, 로그인, 회원가입, 회원정보 수정/탈퇴, 게시판 목록/검색/페이징/상세/등록/수정/삭제, 관리자 회원관리, RAG 검색, 이미지 캡셔닝, 이미지 생성, STT, TTS.

Django에는 React 전용 API를 추가했습니다. 예를 들면 `/api/members/login/`, `/api/members/profile/`, `/api/boards/`, `/api/ai/rag/query/`, `/api/ai/caption/`, `/api/ai/generate/`, `/api/ai/stt/`, `/api/ai/tts/` 등이 있으며, 기존 Django HTML URL도 그대로 보존했습니다.

또한 React와 Django의 포트가 다르므로 `django-cors-headers`, Django Session, CSRF Token, `credentials: include`를 적용했습니다. 따라서 인증 보안을 제거하는 방식이 아니라 **기존 Django 세션 인증을 그대로 React에서 사용**합니다.

실행 순서는 다음과 같습니다.

```text
1. MySQL
      ↓
2. FastAPI : http://127.0.0.1:8001
      ↓
3. Django  : http://127.0.0.1:8000
      ↓
4. React   : http://127.0.0.1:5173
```

브라우저에서는 최종적으로 **`http://127.0.0.1:5173`** 에 접속하면 됩니다. `start_all.bat`도 추가하여 세 서버를 각각 별도 터미널에서 실행할 수 있도록 했습니다.

사용자 환경에서는 `react_frontend`에서 `npm install` 후 실행하면 됩니다.
