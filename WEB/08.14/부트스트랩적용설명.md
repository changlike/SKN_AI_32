기존 **회원관리, 로그인/로그아웃, 게시판 CRUD, 권한처리, MySQL 연동, RAG, FastAPI 멀티모달 연동, JavaScript 기능은 변경하지 않았으며**, 주요 변경 사항은 두 가지입니다.

* 모든 사용자 템플릿에 **Bootstrap 5.3.8**을 적용했습니다. `base.html`에서 Bootstrap CSS와 `bootstrap.bundle.min.js`를 공통으로 로딩하고, Navbar, Card, Table, Form, Button, Alert, Badge, Pagination, 반응형 Grid 등을 적용했습니다.
* `members`, `boards`, `rag` 앱의 함수형 View를 **Class-Based View(CBV)** 로 변경했습니다. 로그인 제한은 `LoginRequiredMixin`, 관리자 권한은 `UserPassesTestMixin` 기반 공통 Mixin으로 변경했고, 기존 URL name과 요청 방식은 그대로 유지했습니다.

예를 들어 게시판은 다음 구조로 변경되었습니다.

```python
class BoardListView(View):
    ...

class BoardDetailView(View):
    ...

class BoardCreateView(LoginRequiredMixin, View):
    ...

class BoardUpdateView(LoginRequiredMixin, View):
    ...

class BoardDeleteView(LoginRequiredMixin, View):
    ...
```

URL도 기존 URL 자체는 바꾸지 않고 `.as_view()` 방식으로 변경했습니다.

```python
urlpatterns = [
    path("", BoardListView.as_view(), name="list"),
    path("create/", BoardCreateView.as_view(), name="create"),
    path("<int:pk>/", BoardDetailView.as_view(), name="detail"),
    path("<int:pk>/edit/", BoardUpdateView.as_view(), name="update"),
    path("<int:pk>/delete/", BoardDeleteView.as_view(), name="delete"),
]
```

`members` 앱 역시 회원가입, 로그인, 로그아웃, 회원정보, 회원정보 수정, 회원탈퇴, 관리자 회원관리 기능을 모두 CBV로 전환했습니다. `rag` 앱도 RAG 검색, PDF 프록시, 멀티모달 화면, Health/Caption/Image Generation/STT/TTS API 프록시를 모두 CBV로 변경하면서 기존 FastAPI 통신 규약은 그대로 유지했습니다.

멀티모달 페이지의 기존 JavaScript가 사용하는 `healthButton`, `captionForm`, `generateForm`, `recordButton`, `ttsForm` 등의 ID도 그대로 유지했기 때문에 기존 `multimodal.js` 기능에는 손대지 않았습니다.
