[리눅스 와일드카드 문자 사용]
와일드카드 (?, *, [], {} 패턴 포함)

 ? : 글자 1개
# ls a?.exe

 ?? : 글자 2개
# ls a??.exe

# ls b?.exe
# ls ??a.exe
# ls ??.exe

 * : 0개 이상
# ls a*.exe

# ls a??*.exe

ex> 첫글자는 a, 두번째글자는 숫자, 총 문자수가 5글자.exe 조회한다면
# ls a[0-9]???.exe

-- vi 3가지 모드:
- 명령모드 (기본) : 커서이동/삭제/복사 명령 수행, esc 키 누름
- 입력모드 : 글자 입력 수행, i (커서 뒤로 추가 기록) / a (커서 앞) / o (새 줄 추가해서 기록)
- 콜론모드 (ex mode) : 명령모드에서 :(콜론) 입력하고 명령어 입력
	:w - 저장
	:q - 종료
	:q! - 저장하지 않고 종료
	:wq - 저장하고 종료

- vi editor 실행하고, find & replace 연습

[리눅스에서 링크(Link)]
 : 리눅스 파일 시스템에서 파일=(이름)+(실제 데이터블록 + inode정보) 로 구성됨
 * inode 정보 : 
	- 파일의 메타데이터(소유자, 권한, 크기, 생성/수정시간, 실제 데이터 위치 등)를 저장하는 구조체
	- 실제 파일의 정보임
 * 파일이름 : 
	- 디렉토리에 저장된 "이름 -> inode 번호" 매핑 정보

*** 같은 inode 번호를 가리키는 이름이 여러 개 있을 수 있음 -> 하드링크라고 함
* 하드 링크 : 같은 inode 를 가리키는 또 다른 이름
* 심볼릭 링크 : 다른 파일 경로 문자열을 가리키는 "특수한 파일"

* 하드 링크 (Hard Link) 특징
 1. 파일명과 같은 inode 를 공유 : 
	원본 파일명과 하드링크는 inode 번호가 동일함
 2. 하드링크로도 파일을 취급할 수 있음 (하드링크명이 파일명으로 사용됨)
 3. 원본 파일명으로 파일을 삭제해도 하드링크가 적용되어 있으면 파일 데이터는 유지됨 (원본 파일명만 삭제됨)
 4. 동일 파일 시스템(같은 파티션)에서만 사용 가능함
	=> 다른 디스크(파티션)에서는 하드 링크 생성 불가
 5. 디렉토리에는 하드 링크 생성 못 함

-------------------------
하드 링크 만들기
- 명령 : ln 원본파일명 하드링크이름
ex>
 ln file1.txt file1_hard.txt

inode 번호와 링크 갯수 확인
 ls -li file1.txt

root@server2:~/link_test# ls -li file1.txt
262222 -rw-r--r-- 1 root root 16 Dec  3 17:03 file1.txt

* 262222 : inode 번호
* 1 : 링크 갯수 (현재 이름 1개)

 ln file1.txt file1_hard.txt
 ls -li file1.txt file1_hard.txt
=> inode 번호 동일, 링크 갯수 2 확인

ex> 한 쪽 이름으로 파일의 내용 수정해 봄
 echo "add line" >> file1.txt
내용 확인:
 cat file1_hard.txt
=> 내용 추가 확인

ex> 원본 파일명으로 파일 삭제해 보기
 rm file1.txt
 ls -li
 cat file1_hard.txt

*** 원본 파일명은 삭제됨, inode 번호와 하드링크이름과 데이터는 그대로 유지됨
*** 백업용 / 로그 보존 용도로 하드링크를 활용하고 있음

[심볼릭 링크(Symbolic Link, Soft Link)]
 - 파일까지의 경로 문자열을 가리키는 별도의 파일 : 
	'이 파일(경로)로 가라'라는 바로가기(shortcut) 개념에 가까움
 - 원본 파일 삭제시
	심볼릭 링크는 깨진 링크(broken link)가 됨
	링크 대상이 없으면 접근 시 에러 발생함
 - 다른 파티션(c드라이브, d드라이브), 다른 파일 시스템(hdd, ssd, usb)에도 링크 가능
 - 디렉토리에도 심볼릭 링크 사용 가능함
	/var/www -> /home/user/www 형태로 자주 사용함
 - 따로 파일로 생성되므로, 경로상의 파일과 inode 는 다름
	심볼릭 링크 파일 안에는 "경로 문자열"이 기록 저장되어 있음
------------------------------

심볼릭 링크 생성:
 - 명령 : ln -s 대상경로 링크이름
ex>
 ln -s file1_hard.txt file1_soft.txt
확인
 ls -l
total 4
-rw-r--r-- 1 root root 25 Dec  3 17:15 file1_hard.txt
lrwxrwxrwx 1 root root 14 Dec  3 17:45 file1_soft.txt -> file1_hard.txt
 
* 파일 권한(permision) : l - 링크 파일을 의미함 (symbolic link)
* -> file1_hard.txt : 이 파일을 가리킨다. 는 의미임

심볼릭 링크 파일안 내용보기
 cat file1_soft.txt
=> 가리키는 대상 파일의 내용이 출력됨

원본 대상 파일 삭제시 동작 확인
 rm file1_hard.txt
 => 깨진 링크는 빨간 글자로 표시됨 (터미널 설정에 따라 다름)
 ls -l
 cat file1_soft.txt => 에러 발생

[디렉토리 링크]
 . : 자기 자신 (현재 위치의 폴더를 의미함)
 .. : 상위 디렉토를 의미함

 - 디렉토리 링크 갯수는 기본 2개임 (자기 자신 + 상위 디렉토리)
 - 하위 디렉토리를 하나 추가하면 부모의 디렉토리 링크 갯수가 1증가함

 mkdir -p link_dir/child1
 cd link_dir
 ls -ld .
=> 링크 갯수 확인 : 3 (자신 + 부모 + 자식)

*** 주의 : 디렉토리에 심볼릭 링크 지정시, 상대경로를 주느냐/절대경로를 주느냐에 따라 디렉토리 이동시 링크 동작이 달라짐

ex> 상대경로/절대경로 심볼릭 링크 테스트
~/link_dir# echo "real data file" > child1/data.txt
 
* 절대경로로 링크 만들기:
 ln -s /root/link_dir/child1/data.txt abs_link.txt
 ls -l
* 상대경로로 링크 만들기:
 cd link_dir
 ln -s child1/data.txt rel_link.txt
 ls -l

* /root 에서 동작 비교
 cd .. 또는 cd ~
* 상대경로 링크 파일 접근:
 cat link_dir/rel_link.txt
* 절대경로 링크 파일 접근:
 cat abs_link.txt

* 디렉토리 위치 이동
 ~# mv /root/link_dir/child1 /root/link_test
    ls link_test
 => 절대경로 링크는 깨짐
 => 상대경로 링크는 링크 파일까지 같이 이동하면, 안 깨짐

* 링크 관련 명령어 -------------
* 링크 상세 보기
 stat file1_hard.txt
 - inode 번호
 - 링크 갯수
 - 권한, 소유자, 크기 등 상세 확인

* 같은 inode 파일 찾기
 find . -samefile file1_hard.txt
 => 같은 inode 를 가리키는 모든 하드링크 이름을 찾아줌
